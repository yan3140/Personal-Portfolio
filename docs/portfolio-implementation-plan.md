# 开发者个人作品集实现方案

## 1. 项目目标

构建一个部署在 GitHub Pages 上的开发者个人作品集，帮助访问者在较短时间内理解：

- 我是谁，以及我专注的开发方向；
- 我解决过哪些真实问题；
- 我在项目中承担了什么职责；
- 我的技术能力、工程判断和工作方式；
- 如何查看源码、在线演示、简历并与我联系。

作品集的核心不是堆砌技术名称，而是通过项目案例和可验证结果证明能力。

## 2. 产品定位

### 2.1 目标访问者

- 招聘人员和用人经理；
- 技术面试官；
- 潜在客户或合作伙伴；
- 开源项目维护者和其他开发者。

### 2.2 核心浏览路径

1. 从首屏确认姓名、开发方向和当前状态；
2. 浏览精选项目，判断能力与岗位是否匹配；
3. 进入项目详情，查看问题、方案、职责和结果；
4. 浏览工作、教育或开源经历；
5. 下载简历或通过公开渠道联系。

## 3. 推荐技术方案

### 3.1 技术栈

- Astro：生成静态页面，适合内容驱动的网站；
- TypeScript：约束配置和内容数据；
- Tailwind CSS：维护设计变量和响应式布局；
- Astro Content Collections / MDX：管理项目案例和文章；
- Lucide Icons：提供统一的开源图标；
- GitHub Actions：执行检查、构建和部署；
- GitHub Pages：托管生成后的静态网站。

默认不引入后端、数据库或大型前端运行时。只有在确实需要复杂交互时，才增加 React 等客户端组件。

## 4. 信息架构

### 4.1 首页

首页按以下顺序组织：

1. 顶部导航；
2. 个人首屏；
3. 精选项目；
4. 工作与项目经历；
5. 技术能力；
6. 开源贡献、文章或其他证明材料；
7. 关于我；
8. 联系方式和页脚。

### 4.2 项目详情页

每个重点项目使用统一案例结构：

1. 项目摘要和封面；
2. 背景与目标；
3. 我的角色和职责范围；
4. 用户、业务或技术约束；
5. 方案与架构；
6. 关键技术决策及取舍；
7. 主要挑战与解决过程；
8. 最终成果和可验证指标；
9. 项目截图、演示或代码链接；
10. 复盘与后续改进。

### 4.3 可选页面

- `/about`：当个人介绍较长时使用；
- `/projects`：项目超过 6 个时使用；
- `/writing`：有稳定技术文章时使用；
- `/now`：记录当前工作和学习方向；
- 中英文版本：仅在确有目标受众时加入，避免首版内容维护量翻倍。

## 5. 设计方向

### 5.1 视觉概念

采用“编辑式开发者作品集”：以清晰排版、真实项目画面和案例叙事为主，融合开发者工具页面的精确感与技术出版物的阅读体验。

- 使用明亮中性色作为主要背景；
- 深色文字保证阅读对比度；
- 使用一个高识别度品牌主色；
- 少量辅助色只用于状态、标签和重点信息；
- 项目截图和结果数据承担主要视觉表达；
- 避免大面积霓虹渐变、玻璃拟态、装饰性光球和假终端界面。

### 5.2 排版与布局

- 正文字体建议使用 Geist Sans 或等价开源无衬线字体；
- 技术标签、年份和少量元信息使用 JetBrains Mono；
- 桌面端采用 12 栏网格，内容宽度约 1120–1200px；
- 正文阅读宽度控制在约 65–75 个字符；
- 卡片圆角不超过 8px；
- 使用稳定的图片宽高比，避免加载时布局跳动；
- 所有固定控件提供明确的 hover、focus 和 active 状态。

### 5.3 首屏设计

首屏应在一个视口内提供：

- 姓名或个人品牌；
- 清晰的职业定位；
- 一句话价值描述；
- 当前状态和所在地；
- 查看项目、查看简历两个主要操作；
- GitHub、邮箱等次要入口；
- 一个真实项目画面、个人照片或具有实际内容的视觉区域。

### 5.4 项目展示原则

- 首页重点展示 3–5 个项目；
- 使用真实截图、流程图或成果图，不使用无关素材图；
- 项目标题下先写成果或问题，再写技术栈；
- 明确标注个人职责，避免让团队成果看起来像个人独立完成；
- 无法公开源码时说明原因，并展示可公开的过程和结果。

### 5.5 响应式与无障碍

- 从 320px 手机宽度开始验证；
- 移动端重新组织信息层级，不做简单等比缩放；
- 所有操作支持键盘；
- 焦点状态始终可见；
- 图片提供有意义的替代文本；
- 动画支持 `prefers-reduced-motion`；
- 正文和控件满足 WCAG AA 对比度要求。

## 6. 内容模型

### 6.1 个人资料

个人资料集中维护姓名、定位、简介、所在地、状态、社交链接、联系方式和简历地址。

### 6.2 经历数据

每段经历包含组织、职位、起止日期、地点、工作模式、职责、成果和相关技术。首页只展示精炼版本，详细简历可保留完整描述。

### 6.3 项目内容

每个项目使用独立 Markdown 或 MDX 文件，包含结构化元数据、正文、图片、链接和 SEO 信息。构建阶段校验必填字段，防止项目页面因缺少数据而损坏。

## 7. 实现流程

### 阶段一：资料收集与内容审计

- 填写 `content-intake-template.md`；
- 选择 3–5 个最能证明能力的项目；
- 检查项目链接、源码权限和图片使用权；
- 将模糊描述改写为问题、行动和结果；
- 标注首版必需内容和可延后内容。

交付物：完整内容清单、缺失项清单、项目优先级。

### 阶段二：信息架构与设计系统

- 确定页面数量和首页区块顺序；
- 形成颜色、字体、间距、圆角和阴影变量；
- 绘制桌面端和移动端线框；
- 确定项目卡片及项目详情模板；
- 输出项目根目录下的 `DESIGN.md`。

交付物：页面结构、设计规范、关键页面线框。

### 阶段三：工程初始化

- 初始化 Astro 和 TypeScript；
- 配置 Tailwind CSS、图标、格式化和类型检查；
- 设置基础页面布局、SEO 和主题变量；
- 建立内容 Schema；
- 添加开发、构建、检查和预览命令。

交付物：可运行、可构建的项目骨架。

### 阶段四：首页实现

- 实现导航和首屏；
- 实现精选项目和项目卡片；
- 实现经历时间线和能力分组；
- 实现关于、联系和页脚；
- 完成亮色、暗色及响应式状态。

交付物：内容完整的响应式首页。

### 阶段五：项目案例页

- 建立项目详情布局；
- 为重点项目录入完整案例；
- 优化项目截图及图片加载；
- 添加上一个/下一个项目导航；
- 处理外链、源码不可公开等状态。

交付物：3–5 个完整项目案例页。

### 阶段六：质量与发布准备

- 添加标题、描述、canonical、Open Graph 和结构化数据；
- 生成 sitemap、robots.txt、favicon 和分享图；
- 添加 404 页面；
- 检查键盘操作、颜色对比度和替代文本；
- 检查所有内部路由和外部链接；
- 压缩图片并检查移动端网络表现。

交付物：候选发布版本和质量检查结果。

### 阶段七：GitHub Pages 部署

- 确认个人主页仓库或项目主页仓库形式；
- 正确配置 Astro 的 `site` 和 `base`；
- 添加 GitHub Actions 构建与部署流程；
- 在仓库设置中启用 GitHub Pages 的 Actions 来源；
- 验证生产环境路由、资源路径和 404 行为；
- 可选配置自定义域名和 HTTPS。

交付物：公开访问地址和自动部署流程。

### 阶段八：上线验收

- 验证常见桌面、平板和手机尺寸；
- 验证亮色、暗色及系统主题切换；
- 验证无 JavaScript 或慢速网络下的核心内容；
- 运行 Lighthouse、链接检查和构建检查；
- 检查简历下载、邮箱和社交链接；
- 使用真实设备做一次最终浏览。

## 8. 验收标准

- 首页在 30 秒内能明确传达身份、方向和代表项目；
- 重点项目拥有完整的问题、职责、方案和结果描述；
- 320px 宽度下无横向溢出和文字遮挡；
- 键盘可以访问所有链接和控件；
- 所有图片尺寸稳定并包含替代文本；
- 所有页面都有独立标题和描述；
- GitHub Pages 子路径下资源和路由正确；
- 推送到主分支后可以自动构建和发布；
- Lighthouse Performance、Accessibility、Best Practices 和 SEO 尽量达到 95 分以上；
- 首版不包含未使用的框架、依赖和复杂动画。

## 9. 开源参考的使用原则

可以参考以下项目的内容组织和工程方式，但不直接复制品牌、文字或完整视觉：

- VoltAgent/awesome-design-md：设计系统和视觉规范参考；
- RyanFitzgerald/devportfolio：集中式个人配置和经历结构参考；
- vito8916/simple-portfolio：Astro Content Collections 与 MDX 项目结构参考；
- Astro 官方 GitHub Pages 指南：部署配置参考；
- GitHub Pages 官方文档：Actions 和发布设置参考。

开始使用任何模板前，需要确认许可证，并保留许可证要求的声明。个人照片、公司 Logo、项目截图和客户数据也需要确认公开权限。

## 10. 首版范围建议

首版优先完成：

- 一个高质量首页；
- 3 个完整项目案例；
- 2–5 段经历；
- 简历下载；
- GitHub、邮箱等联系方式；
- 响应式、SEO、无障碍和自动部署。

博客、复杂动画、访问统计、中英文切换和实时 GitHub 数据可以在首版稳定后按实际需要增加。
